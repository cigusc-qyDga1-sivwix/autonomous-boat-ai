# BOAT LAB v1.1 — 全国開催の自動取得・締切前予想 PWA

GitHub Pages: https://cigusc-qydga1-sivwix.github.io/autonomous-boat-ai/

## 自動で動く機能

- GitHub Actions がJST約06:00〜23:59の間、10分間隔で実行予定。
- 1日分の非公式 Boatrace Open API v1 を取得し、全国24場のうち当日開催している場（最大288R）を収集。
- 発走前に6艇分の出走表が揃えば「展示前暫定予想」を1回固定。
- 締切前に6艇分の展示ST・展示タイム・進入と場内風速・波高が揃った場合だけ「展示反映予想」を1回追加固定。
- 予想はPlackett–Luceに基づく未訓練・未校正の試験用ヒューリスティック。勝率・モーター2連対率・平均ST・コース、展示の簡易重みを使用。2026-10-22以降の新規固定予想のみ、風・波で先頭相対評価の不確実性を調整する試験ルールを追加（精度向上は未実証）。
- 3連単の買い目は**新規予想から4〜12点の可変方式**、各R合計50,000円の仮想金額。頭候補の相対評価と次点差で点数を決め、本線・対抗・穴で配分差を付ける。オッズでの採算判断は未実施。過去の8点固定記録は変更しない。
- 予想時刻・SHA256・2段階のスナップショットを日付別JSONおよびGitコミットに保存。結果データは予想計算に渡さない。締切後は新規予想を作らない。
- 結果照合はBOATRACE公式「本日の払戻金一覧」（https://www.boatrace.jp/owpc/pc/race/pay?hd=YYYYMMDD）を正解として使用。日付・競艇場コード・R番号・3連単・100円配当を照合。発走前固定予想のみ仮想収支に計上。
- iPhoneは起動時と画面復帰時に最新を取得。アプリを開いている間は5分間隔で確認。通知・自動購入なし。

## ファイル構成

- .github/workflows/boat-lab-auto.yml — 定期収集・保存・公開。
- scripts/autonomous_daily.py — 全国取得と締切前固定・結果照合。
- app/data/live/YYYY-MM-DD.json — 日付別・レース別の固定記録と結果。
- app/data/live/latest.json — PWAが読む集約データ。
- .github/workflows/boat-lab-pages.yml — アプリの通常公開。
- tests/test_autonomous_daily.py — 締切後の後出し防止の自動テスト。

GitHub Actionsのcronには実行遅延があり、毎レースの締切10分前を保証しません。非公式APIも数分遅延や欠損があり、間に合わない場合は「未固定」として後出ししません。開催のない日や障害では昨日のデータが残ることがあります。画面の対象日と最終更新時刻を確認してください。

## iPhoneで更新を見る

ホーム画面のBOAT LABを開くと新しい予想データを自動読込。手動更新は右上の↻。手動インポートしたデータが優先される場合は「データ管理 → 元の予想に戻す」で自動配信に戻ります。

- 手入力は公式未取得時のみ暫定扱い。ユーザー提供結果は正式な自動検証成績には加算しない。

## v1.5 展示をチェック → 展開を再評価 → 試験3連単8点（2026-10-22）

このバージョンで **「BOATERSとBOAT LABの予想比較」ではなく「外部の展示指標を参考にBOAT LABの予想ロジックを改善する」** ワークフローへ方向転換。

1. 場・レースの予想詳細で「BOATERSの展示項目を見る」リンクを開く（本人の操作による通常のウェブ閲覧のみ、ページ内容はコピー/自動収集しない）。
2. 「展開を再評価する」→「取得済みデータで再予想（8点）」を押すと、**BOAT LABが独立に取得した**全国勝率・平均ST・モーター連対率・コース・展示タイム/展示STの有効項目から、条件付き3連単8点/仮想50,000円を再計算。
3. 競艇場公式など、利用条件を確認した**権利上利用可能な独立データ**があれば、1周・回り足・直線タイムを6艇分入力して追加補正できる。6艇が揃わない項目は計算に使わない。BOATERSからの手動一括転記/転載やスクレイピングを認める仕組みではない。
4. 勝ち筋は「先マイ／差し／まくり差し」などの試験シナリオ別。1着艇の選定に応じて2着・3着を条件付きで再評価する。ただし統計モデルは**未訓練・未校正**で、実際の確率や優位性を示さない。
5. この端末内の試算は正式な発走前固定予想・GitHub保存記録・公式照合収支を変更しない。締切後の試算は「事後シミュレーション」と明記する。
6. BOATERSの元の展示指標の多くは各競艇場の公式発表に由来するが、**現時点でBOATERSからアプリへ直接取り込んではいない**。自動連携にはBOATERS運営の明示的な許諾が必要。今後は競艇場公式等の許可された取得方法とデータの取得時刻の固定を検証する。

実装: app/forecast-reanalysis.js、app/forecast-reanalysis.css。
テスト: app/tests/forecast-reanalysis.test.js、app/tests/boaters-reference.test.js。

## v1.6 予想点数を固定8点 → 動的4〜12点へ（2026-10-22）

**今後の新規レース予想と展示後の再予想の両方に適用。**

- 先頭艇の相対重みと次点との差が大きいほど4〜6点に収束させる。
- 2番手候補の追走／センター攻め／別線の流れ込みなどを選ぶ必要があれば7〜9点。
- 先頭候補が拮抗し、2着・3着の残存条件に分岐が多いケースは10〜12点まで拡張。
- レースに関係ない一律の8点買いはしない。選定した理由（相対重み・次点差）を表示する。ただしこれらは未訓練ヒューリスティックの指標であり、的中確率や最適点数として校正済みではない。
- 3連単は重複排除し、配分は1,000円単位・各点最低1,000円。本線寄りに重みを付けて**合計仮想50,000円に一致**させる。
- 先頭候補がある程度拮抗している場合は、首位候補だけに買い目が集中しないよう2番目の頭の勝ち筋を最低1点含める。
- 発走前の固定時刻・SHA256を保ち、既存の8点レースは**当時の元データをそのまま残す**。過去レースの表示や公式払戻照合の買い目も変更しない。
- 展示後の手動再評価は従来どおり試験用（スマホ画面内のみ）。発走前正式記録に混ぜない。締切後に生成したものは事後シミュレーションと明記する。
- 同じ開催・同じデータを用いた条件付きモデルの新旧比較で、点数の違いが的中率と仮想回収率にどの程度効くか継続検証する。点数拡張が収支改善になることは保証されない。

実装: scripts/autonomous_daily.py, app/forecast-reanalysis.js, app/app.js。
テスト: tests/test_autonomous_daily.py, app/tests/forecast-reanalysis.test.js, app/tests/live.test.js。

## v1.8 全国開催場・時間帯別気象の自動取込（2026-10-22）

現状: 10/22のGitHub Actions実行で、開催中14場すべてのOpen-Meteo周辺気象予報取得に成功。

- scripts/venue_weather.py で全国24場の**近隣概算座標（会場内測量座標ではない）**を管理。
- GitHub Actionsの自動予想実行に合わせ、**当日レースが開催されている場のみを1回のバッチGET**で取得。風速m/s・風向度数・突風m/s・降水量mm・気温℃・天気コードの予報をJST時刻別に参照。取得元は非商用条件で利用する Open-Meteo (CC BY 4.0)。商用利用の場合は利用契約を確認すること。
- 各レースの締切に一番近い**予報時刻（1時間以内）**の予測値を予想作成前に固定。展示データに実際の場内風速・波高が発走前に存在すれば、そちらを優先し、観測時点と予報の違いを記録。
- 記録は weather_observed（場内展示観測）、weather_used（予想計算に選んだ値）、weather_adjustment（使った試験補正・理由・係数）、weather_ab（気象あり/なしの発走前固定対照）に分離。SHA256と発走前固定時刻に内包。これらは**過去の既存予想には後付けしない**。
- 特定会場の走行方向と気象観測地点の差は未校正。風が強いほど単純に内/外枠有利とするのは危険なため、風速4m/s以上、または波・突風が大きい場合に**先頭候補の確信度を限定的に下げる**試験補正のみ。平常時には評価は変更しない。降水量や風向は情報取得・表示はするが、その値から艇番有利不利を直接決めない。
- 現在の開催場別近隣予報はvenue_weatherに公開し、ホーム開催カードと全12R一覧に表示。発走前スナップショットに固定された気象と、後日更新された参考予報は混同しない。
- 未来の同一レースについて、気象補正あり/なしの買い目を両方**事前固定**して、BOATRACE公式払戻で照合した後weather_backtestを集計する。事後の後出し買い目は一切認めない。
- 一時的なOpen-Meteo通信失敗では、予報値を創作せず weather_fetch_status=UNAVAILABLE。出走表があれば以前の予想ルールで固定できるが、予報利用レースとしては数えない。
- 10/21の競艇AI発走前固定記録はこの競艇リポジトリでは確認できないため、10/21対10/22の正式な前日比較は現在不可。10/22の単日成績や、v1.8導入後の同条件比較を蓄積する。
- 仮想5万円、4〜12点、既存記録の不変、公式結果のみの照合、通知なしは維持。

Open-Meteo: https://open-meteo.com/ , https://open-meteo.com/en/docs
利用条件と表示クレジット: Weather data by Open-Meteo.com (CC BY 4.0)。無償エンドポイントは非商用用途向け。

## v1.9 公式結果を使った予想AIの弱点診断とデータ品質修正（2026-10-22）

**検証例**：10月22日18:37 JSTの公式確認81Rは28R的中（34.6%）、仮想投資405万円、払戻301万8,400円、回収率74.5%。仮想収支−103万1,600円。数字はその後の自動収集で更新される。全て研究用WATCHの仮想5万円配分で、実購入の成績ではない。

- 買い目の筆頭を①頭にしたのは77/81R。実際に①が勝ったのは38/81R。頭候補全体の捕捉率と筆頭艇の偏りは区別する。コース1係数の校正不足が有力な改善仮説。
- 的中28R、頭抜け13R、2着の並び抜け27R、1・2着一致で3着抜け13R。着順連動型の条件付き予想が最優先。
- 168レース中103Rの予想を事前固定、最終展示反映20R、未固定65R。展示の取得・固定タイミングが不足。
- 103Rのうち97Rが旧8点モデル。4〜12点と気象補正モデルの優位性は少数の結果だけでは判断できない。
- 場別近隣気象予報を14場取得しても、予想に固定できたのは5R、実際に重み変更したのは1R。気象の効果は未検証。
- 保存された618艇分の平均STに0.00が11件、展示STマイナス（展示F）が30件。従来コードは実態より速いSTとして加点する可能性があった。

**データ品質の修正（今後の新規予想のみ）**

- 平均ST 0.00・欠損・範囲外は中立値0.17で計算し、元の数字と補完の有無を記録する。
- 展示F（負の展示ST）はスタートの速さとして加点しない。元の表示値は残す。
- 展示タイム0など異常値を含む展示は確定済み6艇分の展示と判断しない。
- 新規モデル名: heuristic-0.5-st-quality-weather-test-untrained。以前の固定買い目・投資配分・SHA256・成績は変更しない。これによる精度向上を保証しない。
- モーター2連対率0%は真の低い実績と小標本が区別できないため、出走母数が得られるまで機械的な補完をしない。

**継続診断と今後の改善**

- scripts/forecast_audit.py が公式確認済み結果のみ頭抜け・2着抜け・3着抜け・的中の4分類に分け、場別・モデル別・点数別・バイアスを自動集計して app/data/live/audit-latest.json に保存する。
- アプリの「成績分析」に「予想AIの弱点診断」を追加。固定・未固定・展示反映と①頭偏りを表示。
- 次に必要なのは①コース別倍率の再校正、②スタート～1マークの攻め・差しに応じた2/3着条件付き選定、③展示データ取得率改善、④正規取得元の気象・潮位補正、⑤公式確定前オッズによる期待値検証。
- 頭と3着の条件付きモデルの改善を比較する際は、旧モデルと候補モデルを発走前に両方固定し、未来レースの同条件で照合。単日の事後最適化は採用しない。

## v2.0 出走表＋スタート〜第1ターンマーク〜バックの展開アニメ（2026-10-22）

## v1.11 全レース結果の画像・公式URL一括照合（2026-10-23）

**1Rずつではなく、日別払戻一覧（複数場・各場最大12R）を一度に取り込む設計。**

- 「結果照合」の上部に「全レース結果をまとめて照合」を設置。レース単位の旧手動入力・旧読取は必要時のみ折りたたみ表示。
- **画像**：PNG/JPEG/WebP最大12MBの払戻一覧スクリーンショット。端末上でTesseract.js v5.1.1による日本語・数字OCRを実行（初回のみエンジンと言語データの通信取得あり）。画像そのものはBOAT LABサーバーへ送信しない。複数場の横並び表は座標を補助利用、曖昧な場・Rの組合せは原画像で手動確認が必要。
- OCR候補は開催場・R・3連単・100円払戻を行単位で表示。ユーザーはチェックボックスで選択、読み間違いを修正してから「確認した結果を一括反映」を押す。**OCR結果は端末内の暫定記録**、公式確認済み成績に混ぜない。返還・中止・同着を検出した行は原則ブロック。
- iPhoneのテキスト認識で結果表をコピーできる場合は、画像の代わりにテキスト貼り付けでも同じ一括行パーサーを利用できる。
- **公式URL**：BOATRACE「本日の払戻金一覧」 https://www.boatrace.jp/owpc/pc/race/pay?hd=YYYYMMDD だけで日付ごとの全場・全レースの払戻を照合。レースごとの結果URLにも対応する。ユーザーのiPhoneから公式ページを直接スクレイピングするのではなく、GitHub Actionsが既存の厳格な公式HTMLパーサーを使って取得・検証した同日データを読む。
- サーバー側の公式払戻取得に成功したら app/data/live/official-pay/YYYY-MM-DD.json へ保存。前回までに確認した結果は取得の一時的な欠損で消さず、不一致は訂正確認待ちに隔離。新規の予想と結果を混ぜない。
- 一括反映時に公式未収集／返還／中止／競艇場やRが不明／そもそも発走前固定がないレースは正式照合できない。すでに公式確認したレースは二重計上しない。
- URL由来の結果は、対応する当日・開催場・R・発走前固定のSHAを持つ予想にだけ結び付ける。端末に公式確認した結果を保存でき、次のGitHub自動更新ではサーバーの値を優先。食い違いがあれば「要確認」。元の発走前予想や金額は変更しない。
- URLと日付が異なる場合はブロックする。その日の発走前予想データが端末に表示されていない場合は対応できない。最新日の公式払戻は実際のレースが終了・公式掲載・GitHub定期取得されてから利用可能。取得できないデータは空欄のまま。
- 自動テストは位置・日付・読取候補・公式URLと全24Rの対応付け、およびiPhone風のOCR→一括確認→暫定保存／公式払戻URL→一括確認→公式保存をカバー。実際の複雑な画像レイアウトのOCR精度はまだ利用者画像での検証が必要。

実装: app/batch-result-reader.js, app/batch-result-reader.css, scripts/autonomous_daily.py。
テスト: app/tests/batch-result-reader.test.js, app/tests/batch-result-integration.test.js。

## v2.1 展開アニメのブラッシュアップ（2026-10-23）

- 最初のアニメは上位3つの買い目ごとにバック側の3連単順位を描くだけだった。新しい版では**本線の1着艇と2着艇に基づく4種類の旋回仮説**を区別する：①先マイ逃げ、②差し、センター・アウトのまくり、まくり差し。
- 例：1-3-2は逃げ、2-1-3は差し、3-1-5はまくり差し、4-5-1はまくりという説明上の分類（現地実況での決まり手を予測・断定するものではない）。
- 複数の3連単買い目を選ぶと、順位だけでなく1M手前の膨らみ方・ターンの経路も変わる。艇の番号色は白黒赤青黄緑。
- **スタート / 1マーク / バック** の3場面へ直接移動する操作、タイムラインのドラッグ、0.5倍 / 1倍 / 1.5倍速、再生 / 一時停止 / 最初から、各場面の説明・予想着順の強調を追加。
- 画面はiPhoneで縦表示を想定したレスポンシブSVG。元の出走表は艇番、選手名、全国勝率、モーター2連対率の4項目のまま。
- あくまでも **すでに作成した買い目を説明する模式図**。実際の進入・スタート展示動画・艇速・旋回半径・風・艇間距離による物理シミュレーションではない。4〜6番手の順序も便宜的な描写であり予想の対象外。アニメを見ても予想買い目、SHA256、結果照合、払戻成績は変更されない。
- 実装: app/race-visual.js、app/styles.css。テスト: app/tests/race-visual.test.js、app/tests/race-visual-controls.test.js。
