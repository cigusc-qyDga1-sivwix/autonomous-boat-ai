# 前付け警戒／展示進入の必須確認（HOLD gate v1 / 2026-10-23）

## 変更理由
大村6R（2026-10-23）はスタート展示が `1-6-4-2-3-5` だったのに、BOAT LAB の事前固定は `1-2-3-4-5-6` を暗黙に仮定する baseline のままだった。原因の一部は、当該レースの展示記録が取得できず、最終予想のように見えたこと。

## 安全規則
- **全レース**：展示の6艇すべての `course / 展示ST / 展示タイム` を取得・重複なし検証し、締切より120秒以上前に保存した独立バージョンがない限り `entry_exhibition_gate.status = hold`。もともと当システムで実投票・BUYは行わない。
- **前付け警戒選手**：出走表の名前（空白を除いた一致）で `赤岩善生` を検出したら、そのレースは `entry_watch=true`。ほかの前付け選手を網羅した名簿ではない。見逃しを防ぐため、**名簿にないレースも展示確認までは最終判断禁止**。
- **実際の進入変更**：艇番とコースの紐付けが一意な６つの整数、コースが1〜6で過不足なし、全艇に妥当な展示STと展示タイムがある場合のみ「展示進入確認」とする。変更例 `[lane1=course1,lane2=course4,lane3=course5,lane4=course3,lane5=course6,lane6=course2]` → 展示進入順 `1-6-4-2-3-5` を画面に表示。
- **固定**：`baseline` は比較研究のために保存するが **FINALとは呼ばない**。新規発走前 `exhibition` を作った場合だけ別SHA固定が可能。締切後の研究再計算は事後シミュレーション。保存済み SHA は変更しない。
- **画面**：前付け警戒＋展示未確認なら警告し、未確認時に新モデルの戦法研究を有力候補として押し出さない。一般の展示前予想も最終判断保留と表示。すでに公式照合されている仮想収支の履歴は改変しない。
- **安全な失敗**：CSV、非公式プレビュー、GitHub Actionsの取得が遅れたり欠損したりしても、未取得を「枠なりで展示確認済み」とすり替えずHOLD。取得失敗がある以上「展示は100%取得できる」とは約束しない。

## モデルの現状と残る課題
本改良は**取得成功率を増やしたわけではなく、未取得を見逃さない安全装置**。候補の過去進入傾向を自動で収集する仕組み、選手登録番号での同定、スロー/ダッシュ境界・起こし位置・深イン補正、レース単位の再取得アラート、展示と本番進入の差分は次の課題。全国24場の公開データ取得が遅れる場合、締切前にHOLDが解除されない可能性がある。

## 監査可能な公開出力
`app/data/live/latest.json` の `forecast_races[].entry_exhibition_gate` に
`status`, `final_eligible`, `entry_watch`, `entry_watch_racers`, `entry_changed`, `exhibition_course_order`, `exhibition_verified_before_cutoff`, `reason` を記録する。これは**保管済み予想のSHAへ追加しない、派生した表示・最終判断用ゲート**である。

## テスト
`python3 scripts/test_entry_exhibition_gate.py`
`node app/tests/entry-exhibition-ui.test.js`

最低限テスト：大村6Rの進入変更、重複・小数・欠損コース、欠損ST、負値展示ST（F）を速い加点にはしない、締切ギリギリや後付けの記録、前付け候補なしの一般レースでも展示なしHOLD、入力の無変更。

**公式スタート展示≠本番の確定進入。** 本番結果からの進入確認は別工程で行う。
