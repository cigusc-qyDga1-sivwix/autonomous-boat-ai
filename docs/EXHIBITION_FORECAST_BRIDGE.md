# 展示データ → 予想の直接連携（2026-10-23）

## 修正前の不整合
- 定期取得したBoatraceCSV展示は研究用JSONにだけ保存され、予想エンジンはOpen APIのpreviewだけを参照していた。
- 一周・まわり足・直線タイムはモデル重みに反映されていなかった。
- 展示前と展示後の買い目、点数、仮想5万円の配分差がアプリで見えなかった。

## 修正後
1. GitHub Actionsの同一runで**先にCSV収集、次にOpen APIの出走表+展示を組み合わせて予想**。展示の取得失敗時は従来のOpen APIへフォールバックする。
2. 12桁コード、日付、6艇・進入コース一意性、展示ST/タイムの物理範囲、発表時刻などを検査。**実際の予想処理時刻が締切2分前より早い場合だけ**、展示反映予想を作成する。過去レースへの事後適用は一切しない。
3. 展示タイム・ST・進入に加え、**6艇揃った**一周・まわり足・直線を相対タイム補正として入力。欠損した指標は使わず、展示Fは速い合法STとしては加点しない。
4. 元の展示前固定予想を保持して、展示反映版を別バージョンとして固定。展示時の評価が更新された場合は、最大3件の展示スナップショットまで再固定する（同一値の繰り返し保存をしない）。
5. 展示前後の「買い目が変わったか」「追加・除外」「点数変化」「配分変更」「一着候補が変わったか」を検証データに保存し、レース詳細で可視化する。**買い目が変わらなくても、その判断を表示する。**
6. GitHub Actions予定起動を10分刻みから5分刻みへ変更。ただしcronの遅延があるため、5分おきの実行や全Rの展示取得を保証しない。
7. 結果・払戻は展示予想生成に一切渡さない。正式な収支は既存公式結果でだけ照合。モデルの重みは試験値であり、精度改善は未実証。

## テスト
tests/test_exhibition_forecast_bridge.py に、元の固定予想を不変にしたまま展示後の買い目が変わるケース、欠損、STフライング、後出し防止、重複再計算防止、source timestamp確認を追加。

## 公開確認
CI成功と本番Actions・Pages成功後に、発走前に存在した独立ソースから展示反映予想が何R生成できたかを別に監査。完了済みの当日レースを新モデルで再計算する場合は、必ず「事後シミュレーション」とする。
