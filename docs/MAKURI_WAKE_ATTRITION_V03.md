# まくり成功時の引き波・内側艇失速（試験v0.3 / 2026-10-23）

## 提案された現場仮説
「外からまくられた内側の艇が攻め艇の引き波を踏み、立ち上がりの加速を失って、2・3着にも残れず着外になる」という展開を、従来モデルの「内が2・3着に残りやすい」仮定から独立して検証する。

## 公的な根拠
- BOATRACEオフィシャル用語集「航跡」：引き波を越えるには通常以上のモーター力が必要で、加速に不利。 https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/jiten/10/y_069.html
- ボートレース宮島・初心者ガイド「ツケマイ」：外側の艇が自艇の引き波に内側艇を入れ、失速させる戦法。 https://www.boatrace-miyajima.com/beginners.html/pages_php/ga-info.html

これらは**全てのまくりで内側が必ず4〜6着になる**という意味ではない。特に「まくり」「ツケマイ」「まくり差し」「インが先マイ成功」は区別が必要。レース映像での艇間・引き波交差位置はまだ機械的に観測できていない。

## 仮説的ロジック（現時点で「学習済み」ではない）
- 新規の `BoatTacticalModel.forecastWake(input)` のみを v0.3 として導入。既存 `forecast()`（v0.1）・`forecastOutside()`（v0.2）への変更なし。
- 頭に外からの攻撃が成立したという**条件付き**のときだけ、頭コースと内側艇の `go` / `turn` 能力差を調べ、各内側艇に `estimated_exposure`（0〜0.75）をつける。これは実際の引き波量でも的中確率でもない。
- 4コースの「まくり」分岐を高く、3・5・6コースの「まくり差し」系はより低い影響度とする。明らかに弱い攻撃艇は引き波補正ゼロになる。
- 対象の内側艇が次の2着/3着へ残る条件付き重みを引き下げる。**1着自体の車番/艇番補正は変えない**。波を回避して残るケースはゼロにせず候補として残す。
- `app/race-visual.js` の4コースまくり成立を仮定したアニメは、**着外に落ちる内側艇だけ**を1マーク以降で鈍らせ、白い引き波を「仮説」の注記つきで重ねる。発走前の物理予測・実航跡追跡ではない。**前付け時は艇番号ではなく実コースで戦法を識別する**。
- 4〜12点・仮想5万円・通知なし・実投票なしを維持。

## 監査・検証
- `scripts/freeze_wake_trials.js` が、旧 v0.2 / 新 v0.3 を同じ締切前スナップショットから独立して生成し、別の `app/data/experiments/wake-YYYY-MM-DD.json` と `wake-status-latest.json` に保存。締切3分以上の余裕、ソース鮮度45分以内、買い目妥当性を既存のゲートで確認。再実行してもSHAが変わらない。
- 正式予想、既存 `outside-YYYY-MM-DD.json` 、v0.1/v0.2 の固定SHA、正式BUY収支には影響させない。
- モデル有効性は**新たに発走前固定したレースだけ**で比較する。実結果の決まり手が「まくり」「ツケマイ」（ツケマイは通常決まり手ラベルの項目ではなく展開細分類）なら実映像など別根拠がある場合に分離。観測不能なら「引き波直撃未確認」扱い。
- 重点指標：外攻め頭の捕捉だけでなく、**まくられた内側の2着/3着残存誤差、着外予測、後続5・6の浮上、3連単的中・回収率**、回り足・モーター・場別水面を見て、v0.2に対するメリットを検証する。
- 係数はまだ経験的仮説。観測済みの前向きデータが増えたら訓練/検証期間を厳密に分け、改善なければ戻す。
