# BOAT LAB 引き波推論の設計見直し（2026-10-23）

## 旧v0.3の問題と判断
旧v0.3は「4コースがまくるなら1〜3コース艇は引き波に入る可能性が高い」として、go/turn比とコース距離から一律に2・3着重みを引いた。これは**艇間位置、旋回軌道、波の交差と立ち上がり速度を実際に見ていない**。すなわち「まくり確定なら内が飛ぶ」という、検証されていない定型の付け替えになっている。

**対応**：自動収集パイプラインから `scripts/freeze_wake_trials.js` の定期起動を外す。既存のv0.3ソース、過去に固定された記録・SHAは研究履歴として変更しない。旧v0.2の自動比較、公式予想・収支、展示HOLDは維持。v0.3は精度改善版と呼ばない。

## 同一レースで並立すべき仮説
全ての仮説は「内が実際に波を踏んだか」は**未確認**であることを前提にする。

| 展開 | 見るべき事象 | 結果としてあり得る着順 |
| --- | --- | --- |
| 先マイ回避 | 1Cが先に旋回、4Cの攻撃艇の航跡と交差しない | 1C残存、4Cが負ける／2,3着 |
| まくり成功・内失速 | 4C艇の旋回後の引き波へ特定の内艇が入り、加速を失う | *波を踏んだ艇だけ*後退 |
| まくり成功・外も失速 | 5C/6Cが攻め艇の波を踏む／外へ流れる | 外の追走不成立、内の別艇が残る |
| まくり不発・内の抵抗 | 3Cの壁や1Cの先マイで4Cが膨れる | 1C/2C/3Cが残る、5Cのまくり差し |
| 先攻・後続が独自に差す | 外の攻めを見て隙間を選ぶ追走艇が別の航路に進む | 攻め艇は2着/着外でも5Cが1着 |
| 前付けにより起点が変化 | 実進入とスロー/ダッシュ境界が変わる | 4号艇が4コースではない場合など |

「4号艇／5号艇」の例は艇番ではなく**進入コース**で議論し、舟券は最後に艇番へ変換する。まくり・まくり差し・ツケマイを別戦法として記録する。

## 必要な入力と欠損の扱い
1. 発走前：実進入（スタート展示・可能なら本番直前予測）、スロー/ダッシュ・深さ、選手・モーター・ST・ターン能力、気象水面、過去進入・攻め癖。
2. 学習ラベル（レース終了後にのみ追加）：スリット位置、1M進入前の内外関係、旋回出口の艇間、引き波を踏んだ艇と時間帯、加速回復、バックの隊列、決まり手・確定着順。これらを実際の映像や検証可能な観測データから抽出する。**決まり手ラベルだけで「誰が引き波を踏んだ」を創作しない**。
3. 映像や位置推定がない時は `wave_crossing = unknown`、`exit_speed_loss = unknown`。前付け予想に必要な6艇展示が取れない時は別の展示HOLDが効く。未観測を低い/高い失速確率に自動変換しない。
4. 訓練と前向き検証は日付で分ける。教師ラベルの証拠がないレースを「波直撃」として教師データに入れない。

## UI
- 現行アニメの失速は**初期OFF**、利用者が「引き波直撃を仮定」を選んだ時だけ1M付近の内側艇を鈍らせる模式表示。
- 画面の絵は観測された航跡や物理シミュレーションではない。選択した仮説が筋の通るかを目で確認するだけ。比較・正式予想・自動凍結・収支には反映しない。
- 1着→2着→3着の組合せが出ても「誰が波を踏んだ」の正解を得たことにはならない。

## 技術メモ
異なる展開ごとに `slit_state` → `first_mark_entry` → `attack_path` → `wash_crossing_by_boat` → `turn_exit_by_boat` → `backstretch_order` を有向シーケンスとして持たせる。各ノードに事実/推定/未確認の区別を記録。新たな補正係数は観測データと性能検証がそろうまで正式モデルへ採用しない。
