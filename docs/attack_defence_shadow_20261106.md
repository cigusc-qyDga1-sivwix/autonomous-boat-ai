# 攻防・イン防御・カウンター展開の前向きシャドー検証（2026-11-06）

## 観測された問題（後知恵で予想を作り直さない）

11/5・6の発走前固定予想と公式照合では、15〜18時の的中率が
11/5 **9/32=28.1%**、11/6（17:52頃時点）**8/29=27.6%**。
頭抜けはそれぞれ **14/32**、**12/29**。住之江と丸亀の
同時間帯は合算23Rで2的中。**原因の確定ではなく調査対象**。

夜を含めた時間帯比較の標本は不均等で、場・開催日・選手構成が
変わるため「午後だからモデル係数を変更する」のは禁止する。

## 実装

- \`scripts/attack_defense_shadow.py\` は **本番v2.2の同じ120通り**の
  正規化済み相対スコアから開始。選手の能力・展示データ・風を
  もう一度足し合わせるのではなく、仮説的な**相対順位の小さな変更**
  として上限16%の補正を別計算する。
- コースは艇番でなく**実進入**を使う。平均ST差・展示タイム差を
  1コースとの対比で判定し、展示F、補完平均ST、同じ程度の展示値を
  「明確な攻め」扱いしない。信号がなければ影響ゼロ、シャドーを作らない。
- 攻め成功、内艇の抵抗、攻めが外に流れて2・3コースが差す場合、
  1コースが2着に残る場合、実際の攻め艇外側の追走艇が残る場合を
  **条件分岐としてスコア付けするだけ**。映像なしで実際の牽制・旋回を
  観測したと主張しない。技術的には特徴が既存v2.2と相関するため、
  二重計上リスクをメタデータに明示する。
- 本番 \`scripts/autonomous_daily.py\` では、**正式展示を締切前に確認できた
  レースだけ**並走計算する。本番の買い目・点数・配分・モデル名は変更しない。
  追加の \`attack_defence_shadow\` は \`model_role=shadow_validation\`、
  \`not_formal=true\`、\`result_data_used=false\` として新規固定SHAとともに
  保存。既存の発走前固定予想を再構成しない。
- 計算失敗時も本番を阻止しない。江戸川は既存ポリシー通り除外。

## 勝ち負けを分けて検証

\`scripts/audit_attack_defence_shadow.py\` は発走前の
同時点に保存された本番とシャドーのみを、公式払戻確定後に照合する。
予想生成前に公式結果を読まない。発走後にシャドーを生成し直さない。

\`\`\`bash
python -m unittest discover -s tests -p 'test_attack_defence_shadow*.py'
python -m scripts.audit_attack_defence_shadow \
  --ledger app/data/live/2026-11-07.json \
  --out /tmp/attack-defence-audit-2026-11-07.json
\`\`\`

集計は**同一点数の比較のみ**とし、点数の異なる試験版を
見かけの的中率に混ぜない。午前／12〜15時／15〜18時／夜、
各レース場の的中・回収・頭抜けの改善と悪化を対照表示。
発走前にシャドー未作成のレースを遡って比較に入れない。
11/5・6の既知の失敗レースで係数調整して「改善した」とは主張しない。

## 昇格基準

1. 同一事前情報で**100R以上**（うち住之江・丸亀の15〜18時を
   別集計）を前向き確定する。
2. 頭抜け減少だけでなく、別の頭抜けの増加・2着抜け・
   同一点数の的中率と仮想回収率を併記し、偶然の高配当のみで判断しない。
3. 展示前や不完全展示への拡大適用は禁止。
4. 改良の寄与が有意でない／明確に悪化する場合は試験を停止し、
   正式v2.2を維持する。実投票・通知には接続しない。

## 気象との区別

気象は既存の独立した補正ルートに残し、今回のシャドーは
**気象の影響を上書きしない**。場による補正は実際の場・R別結果で
前向きに確認するまで追加しない。
