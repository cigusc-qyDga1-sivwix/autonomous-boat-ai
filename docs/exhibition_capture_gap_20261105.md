# BOAT LAB 展示取得・正式反映の運用監査（2026-11-05）

## 結論

この修正では、**展示が取得済みでも正式予想に反映されない理由の判定精度を改善**する。
実際の予想生成・固定時刻・点数・既存SHAは変えない。

### 確認したコード上の時刻条件

- `autonomous_daily.build(enforce_wall_clock=True)` の実運用は `max(SAFE_MARGIN_SECONDS, 180)`、つまり**締切3分前**を要求する。
- `entry_exhibition_gate.summarize_gate` の表示判定は**締切2分前**までに固定された既存スナップショットを認める。表示判定は新規予想の生成許可ではない。
- 旧 `exhibition_rejection_audit.py` は2分前を使って未反映の原因を診断し、**2〜3分前に展示を収集したレースを「取得可能だったのに反映されなかった」と誤診**していた。

## 11月5日 11:55 JST時点の保存済み実例

- 11/5 津2R：締切 **10:57**、`preview_captured_at_utc` **10:54:29**。実運用安全期限 **10:54:00** より29秒遅い。
- 11/5 芦屋3R：締切 **09:27**、取得 **09:24:27**。安全期限 **09:24:00** より27秒遅い。
- 津1Rも取得時刻が締切3分前の安全期限を超えている。
- 江戸川は研究収集データにあっても、2026-11-05 08:15 JST以降は本番予想対象から除外。

これらは**監査上の「原因候補」**であり、取得ログだけから実際の将来のデプロイ完了時刻まで保証するものではない。過去レースを正式予想に遡及変換することはしない。

## 本PRの実装

`scripts/exhibition_rejection_audit.py`：
- 実際の180秒の運用期限を基準に分類する。
- 各レースに `production_safe_deadline_jst` と `seconds_captured_before_production_deadline` を追加する。
- 「締切3分前に取得できなかった」「場別運用ポリシーによる除外」「個別取得時刻が不明」を分ける。
- 不完全な記録の日時を推測補完しない。履歴の研究データだけで正式予想が存在したと断定しない。

`scripts/test_exhibition_rejection_audit.py`：
- 津2Rと芦屋3Rの時間差、江戸川除外、欠損証拠、発走前固定の非改変を回帰試験。

## 次の優先作業

1. **取得開始を前倒し**：現在の5分間隔のGitHub Actionsに実行遅延があるため、締切前3分の安全窓に確実に収まる保証はない。処理時間の実測後、より短時間な専用収集の実装可否を評価する。
2. **レース別ステータス**：入手済み・6艇検証済み・正式固定済み・公開完了・安全期限切れを別々に記録する。
3. **結果の前向き監視**：次の開催分で締切前の取り込み成功割合と公開までの遅延を監査。5分cronを増やすだけでは競合や遅延が増える恐れがあるため、無検証で倍増しない。

本PRは既存の正式買い目・実績・デプロイフローを変更しない。
