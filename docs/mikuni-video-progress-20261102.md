# 動画解析の入力修正と実再生確認（2026-11-02）

## 今回進めたこと

動画解析を最優先とする依頼に従い、既存の無人ブラウザ経路を修正した。
許可の取り直しや利用者PCの操作は要求していない。

| 問題 | 修正 |
| --- | --- |
| 旧 `streamer26pi.php` のみ認識し、実際に公式UIから開いた `streamer26pj.php` を拒否 | 両方を限定許可し、日付・展示区分・場・Rの完全一致を維持 |
| R番号を引数に取るのにクリック位置の検査が1R画像に固定 | 選択した1〜12Rの番号で画像を検査。PNG/GIFに対応 |
| 同じプレイヤーのタブとmain frameが2候補になり、曖昧扱いで処理停止 | 同一surfaceだけ重複除外。別タブ・別iframeの曖昧さは保持 |
| ブラウザ画像は最大1920pxを受け付ける一方、追跡器は640px上限 | 元画像の寸法・変化を検査後、解析入力のみ縦横比を保って640px以下へ縮小 |

プレイヤーの視聴拒否を明示する状態も追加した。`play()`が解決しない場合の待機を制限し、拒否表示のある映像に再生を繰り返さない。

## 検証

`python -m scripts.run_mikuni_vision_tests`：74テスト成功、スキップ0。
実際のFFmpegデコードを使う合成映像試験と、Full HD画像の解析入口試験を含む。
これは実レース6艇の認識精度を実証する試験ではない。

ブラウザ経路の回帰試験を、依存不足・スキップで成功扱いにしない必須スイートへ追加した。
GitHub上のWindows/Edge診断は、1Rの通常モードと2Rのウィンドウ表示モードを実行し、数値JSONのみを短期artifactに残す。
PRおよびmain更新時にも診断を実行するよう接続した。ジョブ成功と実再生成功は、JSONの状態を読んで区別する。

## 実ブラウザで確認した事実

1. 公式JLC展示一覧から2026-10-28三国1RをUI操作で選択し、新しい `streamer26pj.php` のURLへ遷移した。場・日付・Rは一致。
2. 外部プレイヤーは「この動画の視聴は許可されていません」「エラーコード：0」を表示。一度再読込しても同じ表示だった。地域/IPが原因かは未確定。
3. 別経路として公式YouTubeチャンネルの「スポーツクラブ新田塚アーク杯 最終日」の保存配信を開いた。動画ページは存在したが、通常の再生と一度の再読込後にも `currentTime=0`、`readyState=0`、`videoWidth=0`、`videoHeight=0` だった。映像フレーム取得成功とは扱わない。
4. 実映像による6艇識別、旋回・出口加速の計測、動画反映済み発走前予想は、今回のブラウザ観測では0R。

公式ページを開けたこと、再生ボタンを押せたこと、合成映像テストが通ったことを、実映像の解析成功へ読み替えない。

## 継続する作業

GitHub Windows/Edgeで公式UI選択後のプレイヤー状態を取得し、今回修正した選択・URL認識の問題と、配信側の視聴可否を分離する。
再生が進む環境では、既存のメモリ内フレーム処理へ渡して候補追跡の数値を取得する。
実映像で艇番識別とカメラ補正を独立確認した後に、展示映像の解析値だけを使う発走前の別試験へ接続する。
直接MP4の入力設定がないことと、公式ブラウザ上でも映像を受信できないことは別の状態として報告する。

正式予想・保存済み買い目・資金配分・結果台帳の変更は、この修正の対象外。
