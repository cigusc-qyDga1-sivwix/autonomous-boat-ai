# BOAT LAB — 展示数値の発走前反映を検証可能にする（2026-11-03）

## 対象と非対象
対象は**数値展示**（6艇の進入、展示ST、展示タイム、入手できた場合は6艇分の一周・まわり足・直線）。展示映像・実投票・BUY昇格・正式モデル係数の変更は今回含まない。

## 固定までの判定
1. OpenAPIのレース別プレビューが6艇完備ならその場で採用し、取得元 `BoatraceOpenAPI` と予想ジョブ内の取得・処理時刻を記録する。元データの公開時刻は不明なら「不明」として扱う。
2. 不完備ならBoatraceCSVの同日レースを検査する。**実際に記録された取得日時・展示値のSHA・取得元の時刻・締切安全余裕**すべてが適格な場合だけ採用する。後からダウンロードした履歴を発走前取得に読み替えない。
3. 新しい展示版は、保存直前に6艇の `course` / `exhibition_st` / `exhibition_time` を、処理に渡した数値と照合する。オリジナル展示が6艇完備していればその全項目も一致必須。不一致なら展示版を作らず、既存の固定版を保存する。
4. 正式な展示予想として成立したレースには、固定版SHAに含まれる `exhibition_input_check` を追加する。これは**数値がモデルの入力と記録に反映された証拠**であり、買い目が変化・的中するという主張ではない。
5. すでにOpenAPIの展示版があっても、締切前に6艇数値が変わった場合は新しい版を追記する（既存の回数上限の範囲内）。同じ数値なら重複保存しない。
6. 予想ダッシュボードに、場別の締切前展示固定数・新規一致チェック数・OpenAPI/CSV別件数と、買い目・配分の実変更数を表示する。過去の固定版に新監査の成功を後付けしない。

## 次に検証すべき外部依存
- 収集ジョブが各締切の安全余裕より前に継続稼働しているか（Issue #148）。
- 6艇分の展示情報が実際に公開された時刻と、収集ジョブの取得時刻を混同しない。
- 取得対象R・完備R・締切内固定R・数値一致R・買い目変更Rを場別に日次記録する。
- 展示未取得により予想が暫定のままのレースは正式的中・正式BUYに読み替えない。
- 改善成績の判定は、同一レース同一点数・発走前固定版の比較に限定する。
