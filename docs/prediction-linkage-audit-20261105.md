## 未接続・未達（確認済み）

### P1: 取得した選手情報の一部が最終メインに届かない

全国3連対率、当地勝率、モーター3連対率、枠別勝率、枠別平均STを一項目ずつ変更しても、v2.1のメイン着順評価・買い目は不変。その一方、保存される旧4要素倍率は変化する。実保存データでも864艇に選手コンテキストが存在するので、単なる取得欠損だけでは説明できない。

根拠: `scripts/autonomous_daily.py` の `features` は主に全国勝率・モーター2連対率・平均STなどから基礎重みを作る。`interaction_primary` は `scored_weights=weathered` を受け、新メインを生成する。`app/four-factor.js` の詳細選手コンテキストを用いた倍率は `promoted` 側に残るが、新メインの基礎入力になっていない。

対応案: 現行主入力と旧4要素入力の仕様を一本化する候補を別に作り、二重計上を除去して同入力で差分検査する。取得済みだから全部足す、という修正はしない。採用には時系列の前向き検証が必要。

### P1: 旧引き波・場別戦法の計算は新メインの着順生成に使われていない

旧ブリッジの `wake_v09`、`role_coverage`、4要素情報と旧買い目を置換し、点数だけ維持する診断でも、最終v2.1着順評価・買い目は不変。`start_v07`、`coupled_v06`、`wake_v09`、`four_factor`等は旧計算から保存され、新メイン120組の生成は別関数で行われる。

新メインに抵抗・攻め流れ・追走の仮説はあるため「艇間作用が皆無」ではない。ただし、旧1M/2M引き波モデルを引き継いで連動している、と扱うのは誤り。上位の `role_coverage` は132Rすべて旧値で、正式な参照元は `interaction_primary.main_role_shares`。

対応案: 診断値のモデル帰属を明示し、最終予想に適用された入力・分岐だけを表示する。引き波の正式接続は別検証とし、図が動くことを予想への反映と扱わない。

### P1: 展開分岐は固定で、レース条件から成立しやすさを推定していない

`interaction_scenarios.evaluate` の5分岐重みは30% / 28% / 17% / 15% / 10%の固定仮定。すべての入力変更試験でも不変。これらは実測の発生確率ではない。

攻め艇は実3〜6コースの基礎評価最大の1艇のみ。2コース艇は専用の攻め艇候補に入らない。2コース頭の組合せ自体は存在するが、2差し・2直まくりの専用成立分岐を評価したことにはならない。STと展示タイムは上流の単一強度に含まれるだけで、層内でST差を条件に攻め成立率を変える処理はない。

対応案: 2差し、複数攻め手、内抵抗、攻め不発、追走成立/不成立を別の条件として設計し、事前情報で検知可能な条件を検証する。固定仮定を観測確率と表示しない。

### P1: 選手別過去戦法の接続口はあるが通常自動運転では未投入

`--tactics-json` の入力が必要。通常ワークフローはこの引数を渡していない。実保存132Rはすべて `racer_course_tactics.status=UNAVAILABLE`、適用0R。テストで適用可能でも本番で取得・投入している証拠にはならない。

対応案: 許諾・選手ID・実コース・取得時刻・過去期間を確認できる供給経路を作る。データなしの牽制/被牽制回数は推定事実として埋めない。

### P1: 江戸川除外は全体に適用されていない

新艇間連動・場別戦法からは江戸川を除外しているが、収集全体からの除外ではない。実保存では江戸川12Rを旧v1.3で予想出力している。

対応案: 今後生成する対象の除外範囲を統一する。過去記録を削除せず、履歴保存と今後の予想対象を分離する。

### P2: 画面ラベル・アニメは完全なモデル同期ではない

主な1着評価と買い目は一致した保存元を参照する。一方、`app/venue-board.js` の一覧モデル名はv2.1を列挙せずv0.7へフォールバック。`app/race-visual.js` の一部ボタンはモデル名の文字列判定でv2.1を「四要素」と表示する。アニメの戦法・軌跡はコースによる描画仮説で、保存済み5分岐を物理的に再現したり、実映像で観測した動きではない。

対応案: モデル識別を共通化して一覧・詳細を照合し、模式図と最終着順計算の区別を明示する。
