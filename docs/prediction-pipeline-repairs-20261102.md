# 予想・展示取得・公式照合の修繕

更新日：2026-11-02 JST。予想の係数変更や試験の正式BUY昇格は行わない。

## 修正した不具合

1. **予想更新の監視が過去日付で失効**
   予想watchdogが10/27専用だった。実行時のJST日付を共有する継続監視へ変更し、毎日の起動と次の監視への接続を用意した。古い・欠落した予想取得記録を検出したら既存の予想収集を再実行する。稼働中・待機中の収集は重複起動せず、再実行間隔を制限する。

2. **結果更新が予想取得の停止を隠す**
   `forecast-sync-latest.json` は予想収集処理だけが出力する。監視は公開済み監査の更新時刻ではなく、この取得記録を読む。公式結果や監査だけが新しくても、展示・出走表が再取得されたとは扱わない。

3. **結果件数と監査集計がずれる**
   公式結果の軽量更新と過去日照合の両方で、同じ照合済みデータから監査を再作成する。結果が増えない再確認でも古い監査を修復する。過去日は日付別監査へ保存し、当日画面を上書きしない。WATCH等の分類と正式/暫定表示も分けて集計する。

4. **変化した展示に古い取得時刻が引き継がれる**
   レースを初めて見た時刻と、その展示数値を初めて取得した時刻を分離する。進入・ST・展示タイム・独自展示・環境を含む入力のSHAに取得時刻を結び付け、数値が変われば新しい取得記録を作る。ライブ反映ではその証跡を必須とし、未来・締切後の取得や内容改変は採用しない。

5. **不正な1行が全場の展示取得を止める**
   場コード、R、時刻、6艇の進入重複、欠損と範囲外数値を行単位で検査する。無効行を理由別に記録し、他の正常な場の処理を続ける。展示Fは有効な観測として保持するが、速い合法STとしての加点はしない。

6. **副次比較の正当な予想が2R除外される**
   メインの4要素モデルは10/29以降最大20点なのに、比較台帳の入力検査が12点上限だった。モデルと発走前日付に合わせて検査し、旧モデルの上限や過去固定記録は維持する。

## 処理順と検証

予想前はCSVの展示4系統を先に取得し、結果・払戻は予想固定後の研究処理で取得する。公式照合は引き続き公式払戻のみを用い、非公式結果を正式実績にしない。

- Pythonの回帰検証で、締切後の改変拒否、取得時刻の結び付け、日付切替、監視の復旧と重複防止、古い監査の修復、過去日の分離を確認。
- JavaScriptの既存67テストを確認。
- 11/1の保存データで、監査153R/71的中という古い値を、実際の照合済み164R/74的中へ再計算。固定買い目は変更しない。
- 11/2の156Rの入力で、4系統の副次比較をそれぞれ156R・エラー0件まで生成できることを確認。これは入力互換性の検証であり、過去日の新規発走前予想と主張しない。
- 事後研究のシミュレーションのみ、取得証跡の検査を明示的に外す。その出力は正式予想へ接続せず、研究用として維持する。

## 運用上の判定

新しい開催分も、展示前は暫定WATCH、6艇の展示を締切前に取得して固定できた買い目だけが展示反映済み。監視やテストが通ったことは、展示の配信遅延解消や予想精度の向上を実証したことではない。

未取得の展示を補作せず、締切後の情報で事前固定を再構成しない。動画の正規入力接続・実映像6艇識別、展示指標別の寄与評価、点数枠なし試験の恒常運用、個人別の実測2/3着率は別の研究・接続課題として残る。
