# BOAT LAB v1.8: 「選手評価」と正式買い目の乖離を修正

確認日: 2026-11-04

## 根本原因
1. app/racer-rating.js の「活躍期待」は、メインが既に保存されていても別の BoatTacticalModel で計算し直していた。
2. app/race-visual.js の「AI優位1着順位」も別のブラウザ戦法モデルを呼んでいた。
3. 保存されている旧4要素の基礎評価と、v1.8で実際に使うPython基礎重みは異なる。旧4要素をメイン予想の直接の計算根拠と説明するのは不正確。
4. v1.8の選手別・コース別実績の追加補正を行った場合も、1着割合・条件付き2/3着の表示メタデータが補正前の120組から再計算されず、採用買い目のスコアと食い違う余地があった。

## 今回の修正
- scripts/autonomous_daily.py で買い目選択に使用した**最終120組の相対スコア**から、1着・2着・3着の艇ごとの重みをそれぞれ計算し、`interaction_primary.main_role_shares`として発走前スナップショットに保存。
- `head_course_shares`も同じ最終スコアから計算。過去に取得した選手戦法の補正を有効化した場合にも、補正前の数値を流用しない。
- 正式に採用した3連単の各艇を1/2/3着別に数え、`interaction_primary.ticket_role_counts`に保存。各艇の評価値と買い目採用数を表示上で並べ、分岐・絞り込みによる差を説明。
- app/racer-rating.jsとrace-visual.jsでは正式メインで別の試験モデルを再実行しない。旧スナップショットにメイン評価が欠けていたら**不明として保留**し、別モデルの評価を正式メインとして表示しない。
- 選手基礎能力（選手単体の競走実績）とレース内の着順評価は役割が異なるため、区別して残す。
- app/four-factor.jsの旧4要素表示は**参考**と明記。v1.8への直接の計算入力だと誤解される説明をやめる。
- UI・PWAキャッシュ更新と回帰テストを追加。

## 正しく説明すべき差
「1着評価が最も高い艇が、最上位の3連単に必ず入る」とは限らない。120通りを足した1着の相対重みと、各3連単の個別評価は異なる。採択時の点数・相対評価の閾値によって差が生じる。**この正常な条件付き差と、別モデルを混ぜた表示の不具合を区別する。**

## 運用・検証上の制限
- 過去の発走前固定SHA、配分、結果、収支は書き換えない。
- 新しいメタデータは今後の発走前予想に保存する。すでに締切を迎えたレースは事後修正しない。
- 展示進入・展示数値が検証できないときは従来の暫定表示を維持。
- 入力データおよび未校正係数の予測力が向上したと証明されたわけではない。今回修正したのは**評価と買い目の参照元の整合性**。
