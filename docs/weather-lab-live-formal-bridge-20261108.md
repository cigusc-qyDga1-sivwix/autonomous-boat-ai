# WEATHER LAB → BOAT LAB 正式予想連携 v1（2026-11-08）

## 目的と範囲
ユーザー要望「気象情報を正確に取得し、正式な予想に反映」。固定済みの過去SHA・実績は維持し、新しく発走前に生成する予想だけで**場内波高**と**気象庁モデルの近隣予報（風速・風向）**を評価する。既存の選手・モーター・展示・実進入・戦法評価、正式v2.3、仮想5万円・BUY/WATCH/SKIPは維持。

- **現地波高**: 同じレース当日のBoatraceCSV `previews/sui`を予想処理が直接取得し、`weather_lab.monitor.build`で検証する。`weather_lab/data`の夜間集計は**予想入力に使わない**。
- **近隣風**: Open-MeteoのJMA API（気象庁MSM/GSM格子モデルの再配信）で風速・風向・気温・雨を取得。元からあった一般Open-Meteoモデルも独立フォールバック取得。いずれも**現地観測ではなく予報**。場内展示の風速を使う場合は`wind_source=boatrace_preview`として区別。
- **場内波高と風の混在**: 現地波高が時刻検証できた場合、`wave_source=weather_lab_boatracecsv_previews_sui`を設定し、他の予報・展示の風速を残して波高のみを差し替える。片方が取得できなくても他方を偽って「現地実測」としない。
- **潮位・潮流**: WEATHER LABが天文潮位を取得・監視しているが、会場水面への対応・流速観測が未検証。正式予想に**反映しない**。風向もレースコース基準の向かい風／追い風には未変換。
- **出典表記**: アプリ詳細に風と波高の異なる情報源、波高観測時刻、予報取得時刻を表示。Open-Meteoの帰属表示を残す。JMA APIの風向角はコース相対風向ではない。

## 締切前ゲート
- 出走当日、場コード、R、締切時刻をすべて照合。
- WEATHER LABの実際の同一実行の取得処理で、提供元取得時刻・観測時刻・取得完了時刻を記録。原則、波高観測20分以内・提供元キャプチャ15分以内・取得後6分以内、締切3分前より前。矛盾・遅延・欠損は棄却。
- 地域格子予報は、今日の予報モデルでデータ取得から6分以内のみ選択。結果・決まり手・配当・実際の本番STを参照しない。
- `scripts/autonomous_daily.py`から`scripts/weather_live_bridge.py`の同時取得を呼ぶ。ネットワークが不通でも既存予報または無補正での正式予想の継続を優先し、古い情報を新しい観測として再利用しない。
- 予想の`weather_used`にフィールド別出典、`weather_lab_integration`に反映・未検証状態を保存。`weather_lab_bridge`で全国取得状況を表示用のJSONに記録。現行の気象補正は**弱い相対スコア補正**であり、モデルの期待値や勝率を校正したものではない。
- 正式予想の`sha256`は従来どおり生成・追記固定。過去レースのスナップショットを置換しない。

## 実装・検証
- `scripts/weather_live_bridge.py`: CSV波高・JMA予報の同時ライブ取得、出典と時刻の検証
- `scripts/venue_weather.py`: 元情報源の名称を保存
- `scripts/autonomous_daily.py`: 締切前波高の適用・正式予想への固定
- `app/app.js` / `app/service-worker.js`: 出典別・鮮度表示／PWA更新
- `tests/test_weather_live_bridge.py`: 未来・遅延・誤レース・欠損を除外し、発走前正式v2.3の出典・点数・仮想額・SHAを検証
- `.github/workflows/boat-lab-weather-live-bridge.yml`: ネットワーク不要の独立契約テスト

## 追加で必要な検証
1. main統合後、GitHub Actions上で実データを取得し、`weather_lab_bridge`の`onsite_wave_snapshots_collected`と実際の`weather_lab_integration.site_wave_applied`を比較。取得件数と**実際の適用件数は異なる**。
2. 波高・風速のあり／なしにおける同じ発走前入力・同じ点数の対照予想を記録し、公式確定後に場別の頭一致・3連単・回収率を比較。後知恵の係数変更は禁止。
3. レース場のスタート直線の方位が一次資料と照合できるまで、風向を追い風・向かい風へ機械変換しない。
4. API利用条件（特にOpen-Meteo無償枠の非商用条件）を実運用の範囲に照らして確認する。

この連携は「取得した時点で正確と断定する」ものではない。締切前の検証可能な観測と、周辺モデル予報の不確実性を明確に区別した限定的な正式入力である。
