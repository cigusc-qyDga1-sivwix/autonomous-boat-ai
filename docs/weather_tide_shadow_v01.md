# BOAT LAB：風・波・潮の研究シャドー v0.1（2026-11-05）

## 運用境界

正式予想には接続しない。新規の scripts/weather_tide_shadow.py は保存済みの展示研究アーカイブを読み取り、独立した診断JSONを出力するだけ。既存の予想関数、モデル係数、発走前固定SHA、正式買い目、結果照合を変更しない。

- 風速・波高と、その**気象値の観測時刻**を別々に監査する。
- 風向のプロバイダーコードは**未検証のため方位へ変換しない**。スタート→1Mの実測真方位と気象学的な風向（風が吹いてくる方角）の両方が検証済みの場合だけ相対風向を計算。
- 潮位の上昇/下降は、場と検潮所の対応関係が独立に検証され、潮位の基準面、予測/実測、発走前取得時刻が明記された場合にのみ研究値を計算する。**潮位の増減だけで潮流の速度や方向は断定できない。**
- 風速4/8m/s・波高4/8cmの分類は旧試験閾値の再利用で、科学的な予測精度改善は未実証。
- 研究出力に買い目・勝率・資金配分・BUY判定を含めない。江戸川は今後の場別検証対象から除外する。

## 実行方法

リポジトリのルートで実行：

~~~bash
python -m unittest discover -s tests -p 'test_weather_tide_shadow.py'
python -m scripts.weather_tide_shadow --date 2026-11-05 --output reports/weather_tide/2026-11-05.json
~~~

出力先を省くと標準出力に表示する。既存の app/data/live や app/data/exhibition を出力先に指定することは禁止。入力は app/data/exhibition/YYYY-MM-DD.json の過去保存済み研究データ。潮位を追加できる場合だけ --tide-samples で別ファイルを指定する。

対応場の水理的接続、検潮所の代表性、取得可能時間、潮位表基準面と観測基準面を確認するまで潮位データは未取得扱い。海水場すべてに潮流を適用しない。

## 三国3R：時刻の不整合を検知

11月5日の三国3Rのアーカイブでは、風・波の観測時刻 08:50、展示ソース観測 09:30:31、締切 09:39。計算上、気象値は展示ソース時刻より約40.5分前、締切より49分前だった。20分超を**研究用の** stale 警告にするが、これを正式予想へ自動で適用しない。展示が新しくても風・波まで新しいとは限らない。

## 検証仮説と交絡

1. 風：同一場・実際の進入コースで、検証した相対風向と展示ST差、逃げ失敗、まくり・差しの関係を調べる。
2. 波：波高だけではうねり・反射波・引き波を測れない。1Mの攻撃成否と1号艇の2・3着残存、2M逆転を別計測する。
3. 潮：天文潮位は予測値、潮位実況は実測値。潮位差と潮流は同じではなく、検潮所の基準面も異なる。
4. 相互作用：風・波・潮それぞれのデータ品質と単独寄与を先に検証し、十分な前向き標本が集まって初めて複合仮説をテストする。

能力・モーター・展示・実進入・季節・場形状・時間帯・観測遅延が交絡する。予想の後知恵再構成を正式実績へ算入しない。最初の100R以上はデータ品質と有効標本の監査に使い、層別不足なら追加。モデルの有意な改善が検証できない限り正式採用しない。
