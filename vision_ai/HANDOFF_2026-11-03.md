# BOAT VISION AI — 新チャット引き継ぎ資料
更新日：2026-11-03（JST）

## このプロジェクトの目的
BOAT LAB（既存の競艇**数値予想AI**）と切り離して、**展示映像AI「BOAT VISION AI」**を独立に開発する。
対象：適法・許諾済みの展示映像 → 実フレーム取得 → 6艇識別・追跡 → カメラ移動補正 → スタート後の伸び・旋回・1M出口加速・艇間連動の数値候補。
完成後に **バージョン付きJSONによる一方向のデータ連携**で数値AIと前向き比較する。
ユーザーは、数値AIと映像AIの**並行開発**、通知オフ、正式予想の履歴保持を希望。

## 実際にできること／まだできないこと（混同禁止）
**できる：** 合成・既存の未確認トラッカーJSONを入力し、6艇のピクセル上の動き、追跡率、前半/後半の見かけ移動量比などを研究値として記録できる。既存の一部シミュレーション・単体テストは成功。
**まだできない：** GitHubクラウド上での実際の展示動画の継続的自動受信、6艇の実映像での独立した艇番認定、実距離に校正した速度、実映像解析値の発走前検証、数値AI正式予想への自動統合。
**証拠：** `docs/mikuni-video-progress-20261102.md` には公式再生画面へ進んだものの視聴拒否等で実フレームが取得できなかったことが記録されている。サイト到達／再生ボタン操作／合成映像テストは実映像の解析成功ではない。
現在の出力スキーマは `boatlabs.vision_ai.pixel_motion_candidate.v1`、`PIXEL_CANDIDATES_UNVERIFIED`、`eligible_for_formal_forecast=false`、`eligible_for_shadow_forecast=false`、`bets_generated=0`。物理速度・実艇番の確定値ではない。

## 独立AIの開発順（次のチャットで実行するタスク）
1. GitHub main、PR #153、専用CI、三国映像ワークフロー、および直近のJSON状態を**実際に確認**。現状と未確認を分け、取得成功・実映像フレーム取得成功・艇追跡成功を別の指標にする。
2. 映像入力の問題を切り分ける。まずユーザーが許可された**配信元から利用できる公式・正規の直接メディア入力**を特定し、配信元の利用条件を守る。DRM回避、動的トークン抽出、保護されたセグメントURL推測、無断転載はしない。提供元が直接ファイルを提供しない場合は、権限のある代替入力経路（ユーザー提供の許諾済みサンプル動画等）で実画像の検証を先に進める。
3. 実映像の6艇追跡の精度を検証。撮影視点、カメラ追従、艇の重なり、色判定、艇番のすり替わりを失敗事例として記録する。必要なら教師ラベル作成を独立タスクとする。
4. 見かけピクセル速度から実速度へ飛躍しない。カメラ補正と水面座標の校正ができるまで「相対画面動作候補」として扱う。
5. 検証済み6艇・レースID・原映像SHA・取得時刻・検証時刻・単位・品質指標を備えた別スキーマを定義して、**数値AI側へは読み取り専用の橋渡し**を設計。
6. まず映像AI単独の研究結果を保存し、同一レース・発走前固定・同一点数・仮想5万円で「数値のみ」と「数値＋映像」のシャドー比較。正式買い目への昇格は前向き検証後に判断。後出し計算を正式実績に計上しない。
7. 独立動作が安定してから別リポジトリ `boat-vision-ai` 等へ切り出す。**別リポジトリの新規作成はまだ未実施**。ツールで作成できない場合は無理に作成済みと宣言しない。

## 融合時の契約ルール
`event_date` / `venue_code` / `race` / `source_sha256` / `captured_at_utc` / `verified_at_utc` / `model_version` / 6艇のIDと特徴量 / 単位・信頼度 / 締切安全余裕の確認。
レース不一致、日付不一致、6艇不足、取得時刻・検証時刻が締切後、艇番未確認、メートル換算未校正、結果データの混入があれば連携不可。
既存のBOAT LABの `app/data/live`、予想ハッシュ、公式払戻・結果台帳は**映像AIから直接更新禁止**。既存の数値AIは独立運用を維持する。
実投票は行わず、通知はオフ。実映像や静止フレームをリポジトリへ無断保存しない。
